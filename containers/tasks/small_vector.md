# SmallVector [C++ spring]

В этой задаче вам предстоит реализовать упрощённый аналог [boost::container::small_vector](https://www.boost.org/doc/libs/latest/doc/html/container/non_standard_containers.html#container.non_standard_containers.small_vector).

Пользоваться контейнерами из `std` и Boost в решении нельзя, умными указателями (`unique_ptr`, `shared_ptr`) тоже. Разрешены `std::allocator`, `std::allocator_traits`, `std::reverse_iterator`, алгоритмы, type traits и вспомогательные функции вроде `std::move` и `std::forward`.

Напишите шаблонный класс:

```cpp
template <typename T, std::size_t N>
class SmallVector;
```

На хор и выше:

```cpp
template <typename T, std::size_t N, typename Allocator = std::allocator<T>>
class SmallVector;
```

Данная модификация представляет собой вектор, который хранит некоторое число элементов внутри себя в буфере на `N` объектов. **Пока хватает этого буфера, динамическая память не выделяется**. Когда места становится недостаточно, контейнер выделяет динамическую память и переносит туда **все** элементы. Внутренний буфер после этого не содержит живых объектов.

Например, `SmallVector<int, 4>` хранит первые четыре числа внутри себя. При добавлении пятого числа все пять чисел должны оказаться в одном динамическом массиве.

Договоримся для простоты, что тип `T` обязательно имеет move-конструктор и перемещающий оператор присваивания, но не обязательно имеет конструктор и оператор копирования, а также конструктор по умолчанию.

Параметр `N` должен быть положительным. Попытка создать `SmallVector` при `N == 0` должна приводить к ошибке компиляции.

### Конструкторы, операторы присваивания и деструктор

- Конструктор по умолчанию, создающий пустой контейнер с вместимостью `N`.
- Конструктор от количества элементов, создающий указанное количество объектов без аргументов конструктора. Для `int` это нули. Поддержка аллокатора как отдельного аргумента — на хор и выше.
- Конструктор от количества элементов и объекта, создающий указанное количество копий объекта. Поддержка аллокатора как отдельного аргумента — на хор и выше.
- Также поддержать copy- и move-конструкторы и операторы присваивания.
- НА ХОР И ВЫШЕ: Должны поддерживаться и случаи конструкторов и =, когда `N` может отличаться от нашего.
- Конструктор перемещения, перемещающий содержимое другого контейнера.
- Деструктор, уничтожающий элементы и освобождающий выделенную память.

Конструкторы количества элементов, копирования и перемещения используют внутренний буфер, если количество элементов не превышает `N`.

### Оператор []

- Реализуйте оператор `[]`, аналогичный по функциональности оператору обычного вектора. Этот оператор не проверяет границы.

### Методы

- Метод `Size`, возвращающий количество элементов в контейнере.
- Метод `Capacity`, возвращающий количество элементов, которое можно вместить в текущий буфер без перевыделения памяти, **включая уже существующие**.
- Метод `Empty`, проверяющий, пуст ли контейнер.
- Метод `GetAllocator`, возвращающий копию аллокатора (на хор и выше).
- Метод `Data`, возвращающий указатель на начало непрерывного хранилища. Нужны обычная и константная перегрузки.
- Методы `Front` и `Back`, предоставляющие доступ к первому и последнему элементу. Нужны обычные и константные перегрузки.
- Метод `Reserve`, принимающий требуемую вместимость `n` и обеспечивающий вместимость не меньше `n`, не меняя количество и порядок элементов. Если текущая вместимость не меньше `n`, ничего не делает.
- Метод `ShrinkToFit`, уменьшающий вместимость, не меняя количество и порядок элементов. Если контейнер уже использует внутренний буфер, ничего не делает. Иначе, если количество элементов не превышает `N`, переносит элементы во внутренний буфер и освобождает динамическую память; итоговая вместимость равна `N`. Если количество элементов больше `N`, уменьшает динамический буфер до вместимости, равной количеству элементов; если она уже такая, ничего не делает. Для пустого контейнера освобождает динамическую память.
- Метод `PushBack`, добавляющий элемент в конец, как копированием, так и перемещением `T`. Должен иметь strong exception safety.
- Метод `PopBack`, уничтожающий последний элемент.
- Метод `Clear`, уничтожающий все элементы.
- Метод `EmplaceBack`, создающий элемент в конце контейнера из переданных аргументов конструктора — на хор и выше. Должен иметь strong exception safety.

### Итераторы

- Типы `Iterator`, `ConstIterator`, а также их синонимы `iterator`, `const_iterator`.
- Методы `Begin` и `End`, возвращающие итераторы на начало диапазона и позицию за последним элементом. Нужны обычные и константные перегрузки.
- Методы `Cbegin` и `Cend`, возвращающие константные итераторы на те же позиции.

На хор и выше:

- Методы `Rbegin` и `Rend`, возвращающие обратные итераторы. Нужны обычные и константные перегрузки.
- Методы `Crbegin` и `Crend`, возвращающие константные обратные итераторы.

Разрешается использовать `std::reverse_iterator`. Обычный итератор должен преобразовываться в константный.

Перевыделение памяти инвалидирует все указатели, ссылки и итераторы на элементы. Вставка без перевыделения сохраняет ссылки и итераторы на существующие элементы, но инвалидирует прежний итератор конца. Удаление инвалидирует ссылки и итераторы на удалённые элементы и прежний итератор конца. Для присваивания и перемещения сохранение итераторов не требуется.

### НА ХОР И ВЫШЕ

- Сделать allocator-aware контейнер с выделением памяти посредством данного аллокатора.
- Поддержать propagate/select_on_container при работе с аллокаторами.
